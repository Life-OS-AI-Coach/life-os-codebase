# LifeOS AI — Data Tier

This directory owns all **DATABASE** components for the platform.

```
data/
├── prisma/
│   ├── schema.prisma   # Single source of truth for the relational model
│   ├── seed.ts         # Idempotent demo seed (demo@lifeos.ai / Demo123!)
│   └── migrations/     # Generated by `prisma migrate dev` (created on first run)
├── postgresql/         # (volume) reserved for future init SQL / extensions
├── redis/              # (volume) reserved for future Redis config
├── object-storage/     # (volume) reserved for MinIO bootstrap
└── ...
```

## Schema ownership

The Prisma schema lives here (not inside the service) so the data model is
owned by the data tier and can be shared by additional services in later phases.
The NestJS API references it via a relative path in
`services/task-management/package.json`:

```jsonc
"prisma": {
  "schema": "../../data/prisma/schema.prisma",
  "seed": "ts-node ../../data/prisma/seed.ts"
}
```

## Schema application (Phase 1)

For fast local iteration the API container applies the schema on boot with
`prisma db push` (no migration history required). To produce versioned SQL
migrations for review, run from `services/task-management`:

```bash
npx prisma migrate dev --name <change_name>
```

Migration files are written to `data/prisma/migrations/`.

## Runtime stores

| Store   | Purpose                        | Volume          |
|---------|--------------------------------|-----------------|
| Postgres| Primary relational data        | `postgres_data` |
| Redis   | Cache / future BullMQ queues   | `redis_data`    |
| MinIO   | S3-compatible object storage   | `minio_data`    |
